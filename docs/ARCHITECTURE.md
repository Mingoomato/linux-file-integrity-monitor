# Architecture

`fimctl` has a small single-process design:

1. The CLI canonicalizes an existing absolute root and rejects broad system roots.
2. The scanner walks from an opened directory descriptor, uses `fstatat(..., AT_SYMLINK_NOFOLLOW)`, rejects symlinks and mount crossings, opens regular files with `O_NOFOLLOW`, hashes through OpenSSL EVP, and compares pre/post `fstat` state.
3. SQLite stores schema version, root identity, file metadata, and SHA-256. Writes use a transaction, WAL, and `synchronous=FULL`.
4. `verify` compares a fresh sorted scan against the stored baseline. `watch` registers inotify watches and appends event.v1-shaped NDJSON.

The scanner and watcher use directory descriptors to reduce path substitution races. Rename cookies and ordinary per-path event bursts use bounded 256-entry pending tables; unmatched move-in and timed-out move-out observations are recorded separately. Non-rename events coalesce over a 100 ms quiet window and preserve the mask, count, and observation-time range. Settled events become copied jobs in a two-thread hash pool capped at 1,024 outstanding jobs. Workers safely reopen and hash the current file, then place results on a completion list; the event loop commits them in submission order, updates the in-memory snapshot, and writes before/after hashes or explicit unknown/error evidence. An `eventfd` wakes the `poll` loop. At the cap, the loop consumes completed jobs before submitting more, bounding memory while potentially delaying inotify reads. Queue overflow, invalidated watches, new directories, and directory moves trigger a recovery cycle: the process replaces the inotify instance, recursively rebuilds watches, scans current file state, emits differences against the last successful scan, and reports `coverage.healthy` only if watch installation and scanning both succeed. A configurable periodic full scan (default 3,600 seconds) also compares current state with the last successful in-memory snapshot. Neither path updates the SQLite baseline. Failed scans remain degraded and retain the last successful snapshot. The synthetic overflow test does not force a kernel `IN_Q_OVERFLOW`. Inotify was selected for unprivileged event observation; fanotify is not a drop-in equivalent and is not implemented.
